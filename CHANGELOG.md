## 2026-10-22 16:12 UTC

- Replaced hard-coded server ports with a shared registry and automatic free-port discovery. `library/ports.json` lists each local server's default port and the variables that request an exact port: API 8000, annotation tool 8001, results dashboard 8002, deck 8003, Vite 5173, and the browser-test fixtures 8102, 8103, and 8137. The first two fixtures previously used 8002 and 8003, colliding with the dashboard and deck, and the dashboard fixture's port was fixed at 8137.
- When a default is busy, a server takes the next free port above it, skipping other services' defaults within a 20-port window, and logs the move. A port counts as busy when something answers there or it cannot be bound, which also catches wildcard listeners that a macOS loopback bind would shadow. Ports requested by variable or `--port` bind exactly and fail if taken. Hosting platforms' `PORT` therefore still binds exactly.
- `library.ports.serve` now starts the API, annotation tool, results dashboard, deck, and all three fixtures. The annotation tool gained `--port`, and `just curate` passes arguments through. Local servers record their addresses in the ignored `.machina/servers/`; hosted deployments record nothing. The new `just ports` lists services and running addresses. `apps/web/ports.mjs` applies the same rules for the JavaScript tooling. The Vite dev server finds a free port, records itself, and keeps its port across config restarts. Its `/api` proxy resolves the running API on every request. `just check-browser` targets the running Vite server.
- Both Playwright configs pick free fixture ports once in the runner, pass them to workers and fixtures through the environment, and no longer reuse existing servers. Previously, with the deck or dashboard open, `just check-controls` either ran against the wrong server or failed to bind. A pinned fixture port that is taken now stops the run with a clear error.
- Verification: 145 backend tests passed, including nine new port tests. They cover the scan, reserved-port skipping, wildcard detection, strict requests, records, stale-record cleanup, hosted mode, and a subprocess `serve` round trip. Python and JavaScript candidate orders match for every service. In one session, with listeners held on 8000 (wildcard), 8102, and 8137, and the deck and dashboard open:
  - A second deck moved to 8004 and the API to 8005.
  - The Vite proxy followed the API from 8004 to 8005 without a restart.
  - `just check-controls` passed all nine regressions, with fixtures on 8104 and 8103.
  - The dashboard browser tests passed all eight, with their fixture on 8138.
  - `just check-browser` passed all seven full-archive tests through Vite.
  - Requested busy ports failed immediately for the deck and the fixtures.
  - A hosted-mode API with `PORT=8199` bound `*:8199` and wrote no record.
  - The frontend built without the port helper, as in the Docker frontend stage, and the wheel includes `library/ports.json`.
- Limitations: a port can be taken between Playwright's choice and the fixture's start; the fixture then fails instead of moving. Records left by killed processes are ignored once their process is gone; the Python reader also deletes them. With no API running, the Vite proxy falls back to port 8000. Existing test clients that set `127.0.0.1:800x` base URLs are unaffected because they never bind a port.
